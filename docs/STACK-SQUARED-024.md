# STACK² 024 — The Toaster's Useful Delight

**Branch:** \`experiment/stack-squared-024-toaster-useful-delight\`. Draft descendant of the native **STACK² 023 Mycelium Shelf**, never merge or deploy without review and explicit authorization.

## Why this is a real Toaster integration

The source is the original **Haunted Toaster** \`src/full-measure/src/renderer/candidate-move-deck.js\`, pinned exactly to commit:

\`the-static-collective/the-haunted-toaster@74365daa3351555d17482662a9a13cc6a316f1e1\`

Unlike a mock brainstorming list, \`scripts/stack-floor-024-toaster.cjs\` uses the actual original \`dealCandidateMoves\` exported from that inspected original source. It returns the six familiar Toaster moves in original deterministic policy order: **EXPAND, MUTATE, CONVERGE, STOMP, CROSS, CROSS**, with original source-addressed proposal IDs, deal ID, deterministic alternative deals and current-candidate context.

Original Toaster's Candidate Move Deck requires media candidate-style fields. The 024 bridge **explicitly maps verified, held source particulars into a temporary *analogical* candidate family**, not real song/video scores or candidate genealogy. Each \`scoreAddress\` is prefixed \`shelf-particular:\`, not a genuine Toaster media score. No creative material is opened and the renderer is never invoked. The user sees these as *questions and local sketches*, not as an authorized output of the music/video Toaster's scoring model.

The pinned Toaster adapter checks the actual Git HEAD and origin, verifies exact bytes of the original source file against Git's pinned commit, and limits invocation to this single module's pure planner. A neighbor-only arrival thread cannot enable CROSS; proximity never becomes creative compatibility. Missing pin/configuration or tampered source refuses; it never auto-installs anything or runs a script from a browser-selected path.

## What a real person gets

Section **10 / The Toaster's Useful Delight** in Workbench's existing \`/stack-floor\`:

1. Find an actual HELD/HELD relationship in the Mycelium Shelf and select its evidenced filament.
2. Click **Deal six possibilities**. Workbench replays its local receiver's native reLATTE signatures and regenerates the entire current bounded Mycelium graph. A source proposal missing from the current graph cannot be selected.
3. The original pinned Toaster deck produces six addressed suggestions bound to the current receiver state and original graph proposal. A CROSS suggestion is **disabled** if the proposed two particulars have no shared non-arrival evidence-backed relation in the present receiver journal, even if the original Toaster candidate deck would ordinarily permit a two-parent cross.
4. Pick a suggestion to show a small **archival paper-style postcard** with an original Toaster move address, a declared evidence category and the two receiving worlds' source labels.
5. Optionally export an actual \`image/svg+xml\` postcard—locally composed in the browser, source-attributed and explicitly **UNSIGNED**. It is an artifact that can be saved, without pretending it is a Toaster-rendered video, a signed crossing, or an accepted relationship.
6. **Deal another six** asks the same real original Toaster planner for the next deterministic deal (maximum nine positions). It cannot execute, persist, cross, or admit.

The five Mycelium lenses remain just *discovery*; this adapter cannot promote a matching declared address to proof of shared material or ownership. Pinned Toaster move-deck metadata is inspiration, not instructions to perform donor work.

## What each move invites

- **EXPAND:** close reading of signed envelope provenance.
- **MUTATE:** a small, unsent note or question in a different form.
- **CONVERGE:** a compact pairwise archive/field-guide card.
- **STOMP:** consider a counterfactual and what a missing relation would change, without inventing history.
- **CROSS 1 / CROSS 2:** side-by-side poster-card comparison, permitted **as a preview only** if current native Mycelium evidence actually links these two held entries through something stronger than consecutive arrival alone.

Original 023 proposal evidence is attached, and each source pair is spelled out. The human is free to enjoy the preview or discard it. Neither the Toaster's nor Workbench's suggestion is a selection or authorization.

## Separate opt-in

Original STACK² 020/021 native source and receiver configuration must already exist; add:

\`\`\`toml
stack_floor_toaster_enabled = true
stack_floor_toaster_checkout = "/exact/local/original/the-haunted-toaster"
\`\`\`

The checkout must be exactly pinned to \`74365daa3351555d17482662a9a13cc6a316f1e1\`. Only loopback Workbench is supported. **Do not put these local endpoints on a public proxy.**

The actual API has only \`GET /api/stack-floor/delight/status\` and \`POST /api/stack-floor/delight/preview\`, guarded by the previous same-origin local session and exact payload keys \`proposal_id\`, \`deal_index\` (integer 0–8). No accept, commit, execute, media-load, or reLATTE admission route exists.

No additional receiver permissions, signed receipts, relationships, output files on server, or Toaster media artifacts are created. Receiver data is never written, and no per-user personalization is inferred.

## Proof and limitations

- Native CI pins **real GHoT 030**, planZ, **reLATTE R14**, and the exact actual Haunted Toaster Move Deck Git SHA. A synthetic receiving world is separately provisioned in CI, with real reLATTE native P-256 signed HOLD entries, one signed ADMIT (excluded), and one genuine GHoT signature-derived crossing.
- \`tests/test_stack_floor_024.py\` tests six real original Toaster moves, deterministic deal replay, separate alternative deals, evidence-based CROSS refusal, same-origin/session and strict input validation, tampered receiver refusal, real journal/private key byte preservation, and absence of ACT/ADMIT routes.
- \`tests/stack-floor-024.browser.mjs\` uses real headless Chromium to run the preceding ACT → CROSS → HOLD → Mycelium sequence, click a real Toaster proposal, preview the postcard and verify that the SVG export declares itself unsigned and non-authoritative. It captures desktop and mobile screenshots.
- The operation **does not run Haunted Toaster's media renderer or creative model**. The result is a metadata-grounded concept postcard. Actual generative video/audio would require another, separately authorized source-media and composition gate; this PR intentionally does not grant one.
- A six-card deck is an aesthetic organization, not six equally good ideas or a best-choice verdict.
- Only current held source IDs reach this engine. All original donor assertions stay marked independently unverified.
