# STACK² 025 — Pocket Seed Printer

**Experimental draft, stacked on STACK² 024 original Haunted Toaster Useful Delight. Not merged or deployed.** No new web API or server-side generation authority.

## The smallest thing we can actually make

A source-addressed, independently usable **Pocket Seed** is an *original, small composition of already-visible metadata* from one current Toaster move. It contains an observation, a deliberately open question, and provenance pointing back to its exact verified receiving-state and Toaster move.

The user can choose one of three distinguishable outcomes:

- **Field Note:** an archivist's exact observed relationship, with one next question.
- **Open Door:** a gentle human-shareable question, without pretending consent or source identity.
- **Composer Seed:** a small original creative brief to be worked on later under distinct permissions, not instructions to execute the donor.

Each output has three portable presentations generated by the **same pure compositional module**:

1. **.txt** — easy to save, edit, copy into a research notebook, or read offline;
2. **.svg** — accessible, printable moss-and-paper seed card with a deterministic nine-by-nine ornamental green grammar glyph that is **not a QR code**;
3. **.json** — machine-readable manifest containing the exact receiver state reference, original source IDs, version-pinned Toaster move address, selected Mycelium relation proposal ID, declared evidence and explicit authority limits.

This is more than a visual postcard because it is a reproducible, small, provenance-carrying **usable text artifact** and portable structured record as well.

## Exact scope of source material

The module \`static_workbench/web/stack-floor-pocket-seed-025-core.mjs\` consumes **only the existing, source-verified STACK² 024 preview** (which itself cold re-verifies native reLATTE R14 signatures and invokes the original pinned Haunted Toaster Move Deck).

Its source surface is deliberately only:

- sender-declared source world labels;
- original reLATTE crossing IDs;
- selected actual Mycelium proposal and its bounded evidence (one explanatory fact, exact declaration);
- receiver state reference;
- original Toaster source commit, deal identity, and native move address;
- authored, visibly speculative questions that never claim knowledge of unseen source bytes.

It has **no read, upload, fetch, search, execution, signing, storage, receiver mutation, Toaster render, or publication endpoint**. It does not infer that HOLD grants any license to reproduce, share or publish referenced content. The exported notes are locally owned files only after the user explicitly downloads them; a future publisher must make its own permission decision.

The original signed receiver's journal remains the native authority. The downloaded Pocket Seed manifest is **not cryptographically signed** and does not become a reLATTE receipt, a selected relationship or verified identity merely by containing valid source identifiers.

## Human MAKE gate

An existing 024 Toaster proposal selection dispatches a local read-only event. Section **11 / Pocket Seed Printer** then displays the available source metadata and gates a single creative act behind:

- a specific selected *currently evidenced, enabled* Toaster move;
- an explicit choice of purpose (Field Note / Open Door / Composer Seed);
- a separately checked consent box authorizing **one** local metadata-only composition;
- typing **MAKE** exactly.

Building a seed consumes the checkbox and phrase. Selecting a different Toaster card, changing the output purpose, re-dealing six options, or new receiver-crossing events invalidate the current seed and require a new MAKE. The exact source state and original Toaster move are addressed inside the resulting manifest; a new state or purpose gets a different content identifier.

No server call occurs when the user presses MAKE. The deterministic seed ID is SHA-256 over a policy-versioned exact manifest content, with no current clock, device identity, user profile, private key or hidden entropy. The local browser's WebCrypto does only this one digest.

## Declared facts vs source claims

The selected observation can say, e.g.:

> Both signed envelopes declare a matching payload address; the bytes have not been fetched.

It **cannot** say the payloads match at the byte level, that donor content was inspected, that two humans are the same, that the sources are related by authority, or that this output is endorsed by a receiver. If the relation is arrival-only, its observation clearly says proximity does not establish a source relation. Those laws are embedded in the text and manifest.

The original Toaster only **suggests the move**, and the source statements remain signed-wrapper declarations rather than reverified truth about unseen material.

## Negative and positive proof

\`tests/stack-floor-025.test.mjs\` tests:
- byte-for-byte deterministic replay, strict input binding to actual selected 024 card object and the pinned 024 Toaster commit;
- distinct modes and content addresses;
- no source bytes/renderer/receiver changes and no inferred source rights in manifest;
- exact declared provenance, consistent text/JSON/SVG export;
- hostile source-looking SVG/HTML text escaping and refusal for stale cards, forged signatures, missing evidence, incorrect source counts or unauthorized mode.

The CI suite also re-runs original GHoT 030, planZ, reLATTE R14, the authentic Haunted Toaster Candidate Move Deck and previous 019–024 Python tests against synthetic independently created original-signed native receiving-world fixtures.

\`tests/stack-floor-025.browser.mjs\` actually clicks original ACT → CROSS → HOLD → Mycelium → native Toaster six-move deal → purpose select → checkbox → typed MAKE → three downloads. It compares the original receiver journal and private-key bytes before/after MAKE, validates exact metadata in the exported artifacts, proves consent is consumed and mode changes force fresh authorization. Desktop/mobile screenshots are retained in CI artifacts.
