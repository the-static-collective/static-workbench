## The executable trace

1. Workbench reads `webz::static/sanctuary` and `webz::static/orchard/022100` as **fixed first-party logical addresses**. The ordinary visitor portal stays strictly **no-carry**.
2. The visitor explicitly selects a packaged, fictional, public `webz.artifact/v0` JSON specimen, inspects its *exact* SHA-256, checks consent, and separately clicks **Sign and offer parcel through reLATTE**. No page load or GET produces a parcel.
3. Workbench requires a valid local session header and exact preview digest; it reuses its existing clean, pinned reLATTE R14 owner gate at `87006f3265103a8abe387d81597c58aeb39b0beb`. There is no second locally invented signing primitive.
4. The actual `scripts/opaque-roundtrip.ts` seals `relatte.crossing-envelope/v0` with P-256/SHA-256 and creates a file-bundle transport frame. The distinct Orchard `LocalReceiver` signs `relatte.receipt/v0` RECEIVE and its policy-selected disposition.
5. Orchard's first-party receiver policy decided **HOLD** for `fictional-reality-fruit` and **REFUSE** for `fictional-uninvited-spore`. Both have `semantic_effect: none` and `admitted: false`; the sender cannot choose `ADMIT`.
6. Workbench's local stage stores the **exact fixture JSON bytes** and verifies their SHA-256 matches the envelope's `payload_refs` address. A second cold Workbench instance replayed the same request without minting another crossing identity.
7. The Orchard's browser view reads the receiver inbox and exposes public signed envelope/receipt evidence. Merely visiting this page neither offers nor admits material.

### Safety and authority boundaries

- **A signing key isn't a human identity.** reLATTE uses fixture-generated P-256 key material. Signed receipts prove consistency of that fixture signer's records, not authoritative legal/world ownership of the human or a global name.
- **Source fixture bytes ≠ receiver's cryptographic attestation of physical byte custody.** reLATTE's signed RECEIVE covers the crossing envelope and its SHA-256 **payload reference**. Workbench's separately checked quarantine staging establishes byte integrity locally; it does **not** upgrade that into a recipient signature on actual file bytes. Fully independent cross-origin / remote byte delivery is future work.
- **REFUSE isn't deletion or nonexistence.** The spore receipt and source specimen remain traceable without becoming an Orchard object.
- **Neither HOLD nor REFUSE is ADMIT.** No world state, personal account, memory, user image, automatic capability or downstream app was imported or executed by these demonstrations.
- **Browsing ≠ offering.** Ordinary `webz::` navigation, its local voyage journal, WORLD entry/return and read-only inbox/proof GETs remain distinct.
- **First-party world IDs ≠ web security principals.** Both scene pages run on the same Workbench localhost origin; a fully independent trust federation is not claimed.
- **Not installed on the user's device.** These checks ran in GitHub Actions on an isolated test runner. No automatic merge or operator deployment took place.
