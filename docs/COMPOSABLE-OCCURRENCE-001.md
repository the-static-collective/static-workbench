# COMPOSABLE-OCCURRENCE-001 · Rocket-step map (experimental, non-canonical)

One independently source-addressed occurrence may admit multiple separately owned projections **without** promoting any projection to an authoritative event, rewriting an earlier witness, or granting execution.

**Status:** review-only prototype; `static_workbench/composable_occurrence.py` is stdlib-only, pure and not registered as a HOUSE endpoint/adapter. It creates one JSON-ready observation envelope and digest; it cannot authenticate the claimed occurrence, the source, the timestamp, the payload, or the projector. No native ALEX/3rdi/TranchNode/LOADOUT receipt is replaced.

## Boundary of the abstraction

`occurrence_id` is caller-declared; it is **not** generated from matching calendar numbers. A projection must identify the owner, source, method, ID, kind, and a bounded JSON value. Hashes are content-addresses for the transmitted description, **not** independent proof of the event or source. Event occurrence, recording, receipt production, and a person's later interpretation may all have different time coordinates.

Absence is not a zero, refusal, agreement, or proof that nothing happened. Two source identities with the same coordinates remain two source identities; two paths reaching the same projected end point need not have the same history.

No one source system takes ownership of another system's native receipt. The Workbench envelope may reference but must not mint project-native rights. The user determines what may be disclosed or initiated.

## Staged proof

1. **Local:** test pure modules with synthetic, explicitly labeled fixture records; refuse duplicate identities, unknown units, non-finite values, mismatched source/clock frames and fake time.
2. **Cross-project:** exchange a *chosen*, minimal observation packet from one project to another, preserving original source refs and non-claims.
3. **Real data:** separately validate astronomical ephemeris / sensor calibration / local text version before attaching those factual observations.
4. **Human UI:** build explicitly invoked, consent-aware inspection and review doors in each owner project.
5. **Effects only later:** separately version-pinned prepare → execute → inspect → reconcile under project-owned authorization. A mathematical return never activates an effect automatically.

This is a compatibility proposal and experiment plan; project maintainers may reject or adapt it. The working CLOCKWORK-001/002 experimental draft PR is independent and is not silently merged into this branch.
