# APERTURE v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic HumanTerminal APERTURE specimen that preserves raw input, emits bounded unresolved readings, records later narrowing as a new cut, and exposes the history through the local Workbench UI.

**Architecture:** A pure `aperture.py` transducer owns deterministic fixture logic and never mutates prior results. `Journal` gains a dedicated immutable `sense_fields` table so replay survives browser/supervisor restart. FastAPI exposes submit/list endpoints. The browser adds a HumanTerminal view that shows RAW, APERTURE, SENSE FIELD, and TRIAD-candidate output without claiming truth or human intent.

**Tech Stack:** Python 3.11+, FastAPI, SQLite, vanilla browser JavaScript/CSS, pytest.

**Spec:** `docs/frontiers/2026-09-17-humanterminal-aperture-triad.md`

## Global Constraints

- RAW input survives every transform unchanged.
- Possible meaning is not human intent.
- Semantic role is not constitutional posture.
- Unresolved is a successful result.
- Later context creates a new cut and never rewrites an earlier cut.
- The first provider is deterministic; there is no T5/model dependency in v0.1.
- No browser-to-shell execution or cross-project write authority is added.
