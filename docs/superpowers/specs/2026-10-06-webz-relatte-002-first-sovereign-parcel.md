# WEBZ-RELATTE-002 — The First Sovereign Parcel

**Status:** implementation proposal in the human-directed "smash" execution lane; not merged, published, or a replacement reLATTE protocol.  
**Date:** 2026-10-06 (operator local).  
**Owns:** Workbench browser adapter and local first-party fictional parcel.  
**Borrowed authority:** reLATTE R14 at exact clean commit `87006f3265103a8abe387d81597c58aeb39b0beb`, running `scripts/opaque-roundtrip.ts` and its `LocalReceiver`. Workbench does not write its own signing/receiver crypto.

## Purpose

WEBZ-NATIVE-001 already makes `webz::static/sanctuary` and `webz::static/orchard/022100` navigable without assuming authority. WEBZ-RELATTE-002 makes the **first explicit material-carry action**: the visitor in the Sanctuary may select an independently authored **fictional reality-fruit specimen** (small JSON, packaged with Workbench), see its exact digest and destination policy, and deliberately offer it to the Orchard. The Orchard's predeclared policy produces an independently signed RECEIVE + HOLD receipt through reLATTE. A separate fictional **uninvited spore** exercises its fixed REFUSE policy and demonstrates that refused material does not become local inventory.

**Noncollapse:** Simply browsing, inspecting a door, entering a world, reloading, resolving an address or recording a voyage **must never sign, transfer or dispose of material**.

## Existing owner reuse

Workbench already bridges explicit DoorHouse and Field Return actions through reLATTE's opaque-organ R14 bridge. Specifically `static_workbench/field_reseed_crossing.py` contains `RELATTE_REVISION`, `_find_pinned` (verifies exact clean checkout), and `_run_json` (bounded process invocation). Reuse these rather than selecting the latest mutable checkout or minting an imitation receipt. The actual reLATTE bridge signs P-256 ECDSA crossing and receiver-local receipts and verifies stored results on cold replay. The signed artifact payload **reference** alone does not transport the actual JSON bytes, so Workbench must stage and verify the exact bytes separately and state precisely what the signed receipts cover.

## World and custody laws

1. **PREVIEW ≠ OFFER.** GET returns the immutable first-party fixture, SHA-256, declared source/target and destination policy, without creating files or invoking reLATTE.
2. **OFFER ≠ VISIT.** Only `POST /api/webz/parcels/{kind}/send` with existing Workbench session/Origin guard, explicit `confirmation:\"SEND_TO_ORCHARD\"`, and exact preview SHA performs transfer.
3. **SOURCE ≠ RECEIVER.** Workbench builds the donor spec and provides the material. The Orchard receiver is a separately rooted reLATTE `LocalReceiver` with its own signing key and predeclared local policy. The sender cannot supply the receiver disposition in the API request.
4. **RECEIVE ≠ ADMIT.** For `fruit`, the Orchard's policy is `HOLD` (not admitted). For `spore`, it is `REFUSE` (not admitted). Neither executes a capability, alters a user's story, or adds an authoritative world object.
5. **HASH ≠ PROOF OF AUTHOR.** Source payload bytes must match the SHA-256 address in the signed envelope; public keys are generated by the reLATTE fixture and prove **continuity of the fixture signer**, not human/world legal identity.
6. **ARRIVAL ≠ INGRESS.** A clicked portal page doesn't carry material; delivery is a separate explicit request. Both fixtures are fictional, public and non-sensitive. No arbitrary input text, file upload, personal memories, photo, OS path, network URL, secret or identity is accepted.
7. **FAILURE ≠ SUCCESS.** No synthetic fallback when the pinned reLATTE checkout is missing, dirty, timed out, exits nonzero, returns unverified shape, or cannot verify content. Display explicit unavailable/held status.
8. **RETRY ≠ SECOND PARCEL.** The same source fixture and target policy reuse a durable request ID/result and yield an idempotent reply; no duplicate independently signed crossing on retry. Concurrency is bounded by a per-Workbench gate.
9. **ARCHIVE ≠ CANON.** Browser-local voyage logs remain distinct from reLATTE envelopes, signed receipts and Orchard's receiver state. Workbench can display a compact verified-reference summary, not recast it as STORYSHIP canon or SupaBardo admission.

## Staging and receiver trace

Source content is packaged as exact UTF-8 fixture bytes with a stable SHA-256. On explicit POST Workbench writes a bounded candidate file under `state_dir/webz-relatte/v0/staged/` as **quarantine, not admission**, and checks the digest after write. It submits a `relatte.opaque-organ-spec/v0` referencing `sha256:<exact_digest>` and source particular `particular:webz:fixture:<kind>:sha256:<digest>`. The pinned bridge writes durable transport frame/bundle, seals crossing with P-256, sends to Orchard `LocalReceiver` and returns signed `RECEIVED` and the locally selected `R3_HOLD` or `R3_REFUSE`. The response and inbox bind crossing ID, receipts, receiver world, donor kind, staged payload digest and source/receiver policy. Stage bytes are not to be presented as an admitted Orchard artifact.

A pre-checked, fixed receiver policy determines disposition. The caller may choose which fictional specimen to offer, but cannot set `ADMIT`, `HOLD` or `REFUSE` directly. Material handling is sandboxed to an operator-controlled local Workbench state directory. The signed RECEIVED receipt attests to envelope reception, not necessarily physical possession of source bytes; local SHA-256 verification is its separately stated evidence.

## Hard negative cases

Reject without signing: no session header, foreign Origin, missing explicit confirmation, stale/wrong digest, kind outside `{fruit,spore}`, unexpected fields, payload oversized or malformed, changed static asset, missing/dirty/wrong revision of reLATTE, and state-dir file corruption. A forged `crossing_id`, altered payload reference, altered donor family, wrong receiver world, wrong `RECEIVED` receipt, changed `R3_HOLD`/ `R3_REFUSE`, or `semantic_effect` != `none` must not be displayed as verified. Do not automatically retry an outcome whose dispatch is unknown; an operator may explicitly inspect the retained checkpoint.
