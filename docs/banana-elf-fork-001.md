# BANANA-ELF-FORK-001 — Independent Return Before Relation\n\nOne signed consequence can now be offered to multiple independent returners without turning their responses into a vote, score, or consensus process.\n\n    ONE SIGNED CONSEQUENCE\n            ↓\n    frozen Banana-Elf field\n            ↓\n    2–6 named sealed booths\n            ↓\n    independent TAKE / HOLD / PASS\n            ↓\n    reveal only when every booth has returned\n            ↓\n    descendants side-by-side\n            ↓\n    pairwise relation field\n            ↓\n    optional human TAKE\n            ↓\n    ordinary proposal-only reseed\n\n## Frozen source\n\nA fork can open only from an exact `workbench.field-station-state/v0` containing the three landed co-delight facets:\n\n- delightfuler\n- helpfuler\n- curiouser\n\nAll three must carry the same exact signed receiver consequence. Constitutional HOLD silence is frozen alongside them.\n\nThe fork therefore does not ask participants to respond to a paraphrase of what happened. Every booth receives the same attributable consequence and the same exact doors.\n\n## Booths\n\nA fork has 2–6 named booths. Labels are unique within the fork.\n\nEach booth receives a `workbench.banana-elf-booth-packet/v0` containing:\n\n- fork id;\n- booth id and local capability token;\n- returner label;\n- exact source Field identity;\n- exact signed consequence;\n- the three frozen Banana-Elf doors;\n- constitutional silence.\n\nThe token is only a local Workbench booth capability. This remains a loopback single-user instrument, not a multi-user authentication system.\n\n## Sealing\n\nA booth's first persisted return is final for that booth.\n\nWhile any booth remains unanswered, normal fork reads expose only:\n\n- booth label;\n- submitted / waiting state;\n- submission time.\n\nThey do not expose selected door, disposition, note, or reseed.\n\nThe submitting returner already knows what they returned; sealing exists to stop earlier responses from becoming context for later booths.\n\n## Reveal\n\nReveal is automatic only when all fixed booths have returned.\n\nAt reveal, returns appear side-by-side in participant order. The instrument computes no:\n\n- winner;\n- score;\n- rank;\n- majority;\n- consensus;\n- preferred facet.\n\nTwo participants may make byte-identical underlying Field Returns. Their fork submissions still remain distinct because booth identity and returner attribution are preserved.\n\n## Relation field\n\nEvery unordered pair of revealed TAKE descendants becomes one unranked relation aperture:\n\n    Let A's <facet> meet B's <facet>\n\nThe door does not claim the two returns agree. Its law is:\n\n    AGREEMENT != RELATION\n    DIFFERENCE != FAILURE\n    PAIR != CONSENSUS\n    RELATION != MERGE\n\nIf three people TAKE, three pairwise apertures exist. If six people TAKE, fifteen exist. The fork room does not reduce them to a top-N list.\n\nConstitutional HOLD silence remains available in the relation field, including when fewer than two TAKE descendants exist.\n\n## Re-entering metabolism\n\nA relation field is itself a valid read-only `workbench.field-station-state/v0`.\n\nA human can TAKE / HOLD / PASS one relation door. TAKE produces the ordinary:\n\n    workbench.field-return/v0\n      → workbench.field-reseed/v0\n      → status: proposal-only\n\nThe return is stored on the normal Field Return shelf, so the existing explicit chain can carry it:\n\n    TAKE\n      → CROSS\n      → RECEIVE\n      → HOLD\n      → ADMIT\n      → OFFER\n      → ASSIGN\n      → DISPATCH\n\nThere is no fork-specific execution path.\n\n## Actual proof\n\n`scripts/smoke_field_reseed_crossing.py` now proves the real pinned sequence:\n\n    original TAKE\n    → reLATTE RECEIVE/HOLD\n    → GHoT HOLD / ADMIT / ASSIGN / DISPATCH\n    → exactly one bounded task\n    → signed consequence\n    → Banana-Elf three-facet field\n    → three sealed fork booths\n    → two independent TAKEs + one HOLD\n    → reveal\n    → one pairwise relation aperture\n    → human relation TAKE\n    → proposal-only reseed\n    → real reLATTE crossing\n    → GHoT HOLD\n\nThe proof verifies that fork creation, sealed returns, reveal, relation TAKE, and relation crossing create no additional task or execution receipt.\n\n## Laws\n\n    ONE CONSEQUENCE != ONE CORRECT RETURN\n    SEALED RETURN != CONSENSUS\n    REVEAL != RANKING\n    DELIGHT != SCORE\n    RETURNER != REPRESENTATIVE\n    AGREEMENT != RELATION\n    DIFFERENCE != FAILURE\n    PAIR != CONSENSUS\n    RELATION != MERGE\n    TAKE != CROSSING\n    CO-DELIGHT REQUIRES RETURN\n\n## What this experiment can reveal\n\nRepeated forks can now produce attributable lineages of independent gifts, repairs, curiosities, and pairwise compositions without specifying which pattern should dominate.\n\nThat makes a later Strange Attractor instrument possible: observe what recurs in the lineage after the fact, without converting recurrence into a reward signal.\n
